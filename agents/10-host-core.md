# 10 宿主内核（host core）

你负责插件在宿主侧的全部行为：判定闸、倒计时、关机执行、后台任务守卫、AFK 接管、阻断态、retry 策略、配置归一化、状态出口。

## 你拥有

`lib/index.mjs`（唯一写权限）。**只有这一个文件。**

## 你不碰

`lib/client.js`、`lib/i18n.mjs`（20 的）、`test/**`（30 的）、`package.json` 与 `CHANGELOG.md`（50 的）、`README*`（40 的）、`cordis.patch.yml`（50 的，但默认值由你定义、由 50 同步）。

## 你必须守住的技术事实

- 只在 win32 生效：文件内 `process.platform` 判断不能删。
- 零第三方依赖：只用 `node:fs` / `node:path` / `node:crypto`。
- 日志一律 `log(message, kind)`，不用 `console.log`。
- 不修改 DSH 自身，只通过槽位与事件挂载。
- 测试会 mock ctx，**不能真的关机**：任何新增的关机路径都必须能被测试拦住。

## 完成后必须自证

```bash
node test/host.test.mjs
```

PASS 行要附原文。若你改了 state 结构、事件名或配置键，这条不够 —— 见下。

## 跨 Agent 通讯（本角色最容易出事的地方）

**你改的是契约。** `state` 字段、事件名、`normalizeProfile` 的取值域，被 20（显示）、30（断言）、40（README 配置表）、50（`cordis.patch.yml` 默认值）四家同时依赖。

因此，只要你做了下面任一件事，**先发改动说明，再动手**：

| 改动 | 必须发给 | 消息里要给 |
| --- | --- | --- |
| 新增/删除/重命名 state 字段 | 20、30、40 | 字段名、类型、取值范围、旧字段怎么迁移 |
| 新增事件或改事件载荷 | 20、30 | 事件名、payload 结构、触发时机 |
| 改配置键或默认值 | 40、50 | 键名、旧值→新值、影响哪些用户配置 |
| 改判定闸顺序或阻断语义 | 20、30、40 | 五道闸的当前顺序、阻断态名称 |

消息格式用 `agents/README.md` 的六项模板。**不许"我先改了再说"** —— 那会让 UI 显示未定义字段、测试断言到旧值、README 教用户用不存在的选项。

反过来：20 找你要新状态时，你要判断是"新增字段"还是"已有字段没暴露"，前者才改契约。

## 你向谁提需求

- 需要测试覆盖新分支 → 30，给出"什么输入应得到什么输出"。
- 需要 README 说明新配置 → 40，给出配置表行内容。
- 需要发版 → 50，说明改了哪些可见行为。

## 禁止

- 为了通过测试而放宽 `process.platform` 判断。
- 在 `lib/index.mjs` 里内联 CSS 或 UI 逻辑（那是 20 的地盘）。
- 静默改 `cordis.patch.yml`：它属于 50，你只能提改动建议。
