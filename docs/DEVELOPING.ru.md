# Локальная разработка

## 1. Без шага сборки

Исходники — это и есть runtime-код: `lib/index.mjs` — ESM, DSH импортирует его напрямую; `lib/client.js` — самодостаточный бандл, который хост при запуске включает в граф модулей.

```
git clone https://github.com/ltayshark0637/dsh-Shutdown-Guard
cd dsh-Shutdown-Guard
node test/host.test.mjs
```

`npm install` не нужен: в репозитории ноль runtime-зависимостей, и тесты используют только `node:test` и `node:assert`.
(Для команд npm используйте `npm.cmd`: локальная политика выполнения PowerShell запрещает `npm.ps1`.)

## 2. Два теста

```bash
node test/host.test.mjs      # хост: mock ctx, реального выключения нет
node test/client.test.cjs    # smoke клиентского бандла: настоящий client.js на фальшивом React
```

После изменения `lib/**` **нужно запускать оба**; если менялись только документы или скрипты скриншотов, всё равно запускайте `client.test.cjs` (скриншоты генерируются из настоящего CSS в `client.js`, и сломанные стили падают там первыми).

Частые имена утверждений и что они защищают:

| Утверждение | Что держит |
| --- | --- |
| `client-bundle-smoke` | `lib/client.js` можно `require` и отрендерить |
| `i18n-coverage-ok` | наборы ключей трёх языков выровнены (см. раздел 4) |
| `window-page-ok` / `window-tape-ok` | страница плавающего окна остаётся полным документом, а предупреждающая лента следует за состоянием |
| `window-radar-parity-ok` | счётчики страницы окна и боковой панели из одного источника |
| `radar-dots-*-ok` | лимит точек радара, `+N`, aria, фильтрация по root |
| `profile-*-ok` | система профилей: без предсозданных пустых слотов, запоминание последнего выбора, правила очистки |
| `theme-label-ok` / `builtin-palette-*-ok` | именование тем и откат на встроенную палитру Claude |

## 3. Ответственность каталогов

| Путь | Ответственность |
| --- | --- |
| `lib/index.mjs` | Сторона хоста: проверки-шлюзы, отсчёт, выполнение действий, повторы и приостановка выключения, сохранение профиля, HTTP-маршруты, страница плавающего окна |
| `lib/client.js` | Карточка на боковой панели: CSS + React в одном файле |
| `lib/i18n.mjs` | Каталог текстов на трёх языках и разбор языка (`LANGS`, `resolveLang`) |
| `test/` | Два скрипта утверждений |
| `scripts/` | Скриншоты, демо-страница, иконки, помощники выпуска (не runtime) |
| `docs/` | Документация для сопровождающих: ARCHITECTURE, CONFIG, DEVELOPING, BETA, RELEASE-NOTES-STYLE (у первых четырёх есть ещё перевод `.en.md`; RELEASE-NOTES-STYLE только на китайском), а также результат работы `screenshots/` |
| `data/` | Runtime-данные: `config.json`, `events.log`, `ui.json` — не коммитятся |

## 4. Наборы ключей трёх языков должны быть выровнены

`MESSAGES` в `lib/i18n.mjs` берёт `zh` за базу: каждый язык обязан определить **каждый ключ** из `zh`, и количество ключей должно совпадать.
`i18n-coverage-ok` в `host.test.mjs` утверждает три вещи:

1. `LANGS` — это ровно `['zh', 'en', 'ru']`;
2. `missing` из `catalogCoverage()` — пустой объект (ни в одном языке не пропущен ключ);
3. количество ключей каждого языка `=== coverage.base.length` (ни больше, ни меньше).

Тексты на клиентской стороне лежат в таблице `MSG` в `lib/client.js` и тоже должны быть выровнены по трём языкам; при изменении текста правьте обе стороны, иначе в карточке появится «одна фраза по-китайски, одна по-английски».

## 5. Цепочка подключения: после изменений нужно перезапустить DSH

Корень репозитория — это каталог плагина, и DSH загружает его по двум цепочкам:

1. `link:<абсолютный путь к этому каталогу>` в `harness\profiles\web\package.json`;
2. `harness\profiles\web\node_modules\dsh-shutdown-guard` → корень этого репозитория.

**Клиентский бандл включается в граф модулей только при запуске DSH; обновление страницы не загружает новый код.** Изменить `lib/client.js` и смотреть на старую страницу — значит не проверить ничего. То же верно для серверной стороны.

## 6. Скриншоты и изображения для документации

Все изображения для документации генерируются скриптами из настоящего CSS в `lib/client.js`, **ручная правка картинок не принимается**:

```bash
node scripts/gen-gallery.cjs --lang all --matrix   # 18 основных изображений + старый набор страниц
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/screenshot.ps1
node scripts/gen-thumbs.cjs                        # 18 миниатюр страницы настроек + base64
node scripts/gen-demo.cjs                          # docs/demo.html
node scripts/gen-banner.cjs                        # banner.html (затем отрендерить banner.png в Edge)
node scripts/gen-gif.cjs                           # README использует матричные изображения, GIF опционален
```

Частые параметры `gen-gallery.cjs`:

| Параметр | Действие |
| --- | --- |
| `--lang zh\|en\|ru\|all` | язык; `all` генерирует все три |
| `--matrix` | набор из 18 изображений `NN-armed-{a,b,c}-{zh,en,ru}-{light,dark}.png` |
| `--thumbs` | 18 страниц-миниатюр настроек (передаются в `gen-thumbs.cjs`) |
| `--only <substr>` | генерировать только страницы, в имени которых есть подстрока; удобно при правке одной картинки |
| `--state <view>` | переопределить состояние (`off` / `armed` / `hold` / `fire` / `fired` / `blocked`) |

`-Filter` у `screenshot.ps1` принимает шаблон имени файла и сопоставляет только `.html`. **Промежуточные `docs/screenshots/thumb-*.html` и `thumb-*.png` после использования нужно удалить, не коммитить.**

Миниатюры демо-страницы берутся напрямую из `docs/assets/variant-*.png` (GitHub Pages считает `docs/` корнем сайта, поэтому `assets/` — абсолютный путь внутри сайта). При изменении миниатюры обновляйте и `assets/`, и `docs/assets/`.

## 7. Дисциплина коммитов

- **Не используйте `git add`**: в этой версии дважды область подготовленных изменений проглатывала чужие правки. Всегда коммитьте с явными путями:

```bash
git commit -m "docs: …" -- README.md docs/CONFIG.md
git show --stat HEAD          # проверка после каждого коммита
```

- У одного файла в один момент времени только один писатель; прежде чем трогать чужой файл, договоритесь.
- Об изменениях контракта (поля state, имена событий, ключи профиля, ключи текстов) нужно оповещать зависимые стороны.
- Не делайте push и не ставьте теги без явной просьбы; тег должен равняться `version` из `package.json`.

## 8. Частые ловушки

| Ловушка | Симптом | Что делать |
| --- | --- | --- |
| PowerShell пишет UTF-8 с BOM | `JSON.parse` падает на BOM | перед чтением `strip` BOM; профиль писать через `fs.writeFileSync(..., 'utf8')` |
| PS 5.1 декодирует скрипт без BOM как ANSI | обратная кавычка в китайском комментарии съедает перевод строки и выдаёт `Unexpected token '}'` | **в `scripts/*.ps1` только ASCII-комментарии** |
| `node -e` сначала раскрывается PowerShell | `${…}`, регулярные выражения и кавычки дают `SyntaxError` или пустой вывод | писать временный `.cjs` и запускать `node file.cjs` |
| локально недоступны `raw.githubusercontent.com` / `api.github.com` / `codeload` | тайм-аут curl `(28)` | читать файлы GitHub через `https://cdn.jsdelivr.net/gh/<owner>/<repo>@main/<path>` |
| перезапись китайского `.md` через `Set-Content -Encoding utf8` | весь файл превращается в кракозябры, переводы строк съедаются | писать инструментом `edit` или через `fs` в node; для правок вроде номера версии делать **замену байт равной длины**, чтобы сохранить CRLF |
| скриншот не обрезается по краям | на выходе фон Edge по умолчанию | `screenshot.ps1` рендерит только `.html`; `Trim-Png` обрезает только по `alpha==0`, поэтому на странице не должно быть непрозрачного фона |

## 9. Выпуск (кратко)

Изменили видимое поведение → обновите и `CHANGELOG.md`, и `version` в `package.json` → коммит → `git tag vX.Y.Z` → push тега; `.github/workflows/publish.yml` прогоняет тесты на `windows-latest`, затем `npm publish`.
Аутентификация идёт через npm Trusted Publisher (OIDC); токен не должен появляться в репозитории никогда. Подробности — в `AGENTS.md` репозитория.
