# v1.6.1-beta.3 测试指南

> **中文** · [English](BETA.en.md) · [Русский](BETA.ru.md)

## 1. 这是什么版本

`1.6.1-beta.3` 是**测试版**，接在 beta.2 后面继续把「上传脚本、到点执行」这条能力跑通。本文件对应当前这一版 beta，不是历史快照。

- **不要装在产线机器上**，也不要用它去测「真的把工作机按时关掉」。
- npm 的 `latest` 仍然是 `1.6.0`；装 beta 必须显式带版本号。
- beta 期间行为可能随时改，文档以本文件为准。

## 2. 怎么装

```bash
npm i -g dsh-shutdown-guard@1.6.1-beta.3
```

装完**完整退出 DSH 再打开**（macOS 上用 ⌘Q 退出，关窗口和刷新页面都不算）。客户端 bundle 只在启动时编进模块图，只关窗口或刷新页面不会加载新代码；改完代码、升级完插件同理。

已经装着 beta.1 或 beta.2 的，先升到 beta.3 再按这份指南测 —— 本文件的测试项与期望行为描述的都是 beta.3。

回滚：

```bash
npm i -g dsh-shutdown-guard@1.6.0
```

（本机 PowerShell 若禁止 `npm.ps1`，请用 `npm.cmd`。）

平台：`package.json` 里的 `os` 限制已经删掉，macOS / Linux 现在可以正常 `npm install`（行为上的成熟度见 3.6）。

从 beta.1 / beta.2 升到 beta.3**不需要任何手工迁移**：配置 schema 在 beta.1 已经定稿为 4，后续 beta 只改行为、不改配置格式，装上新版本重启 DSH 即可。

## 3. 这一版要测什么

每条都按「怎么操作 / 期望看到什么 / 不符合时是什么现象」写。测完请按第 5 节反馈。

**开始之前先武装。** 插件不会因为任务结束就自己开始倒计时 —— 顺序是「先把卡片武装起来，再去跑任务」。没武装就等，什么都不会发生。

### 3.1 上传脚本

- **操作**：设置 → 守夜 → 自定义命令 → 选择文件，分别试 `js` / `cmd` / `bat` / `py` / `ps1` 各一个（内容可以只有一行无害语句）。
- **期望**：胶囊出现，显示扩展名标志色 + 文件名；输入框能改成自定义显示名；点「移除」后胶囊消失、动作区回到未选状态。
- **不符合**：胶囊空着、显示名改完又弹回、移除后仍能武装。

### 3.2 免责勾选

- **操作**：上传一个脚本，不勾免责直接点「武装」；再勾上武装；然后换一个脚本内容再武装。
- **期望**：未勾选时武装被拒并给出原因；勾上后能武装；**换脚本后勾选自动失效**，需要重新确认。
- **不符合**：不勾也能武装；换了脚本还能直接武装（说明 sha256 校验没生效）。

### 3.3 解释器缺失

- **操作**：在一台**没有安装 Python** 的机器上传 `.py`；或在没有 node 的环境上传 `.js`。
- **期望**：动作区显示不可用并说明原因（缺少解释器），武装被拒；换回 `.bat` 或 `.ps1` 后恢复正常。
- **不符合**：显示可用、到点却什么都没执行，且日志里没有解释。

### 3.4 到点执行

- **操作**：选「自定义命令」，倒计时设成 10 秒，脚本写成**只写一个文件**或**弹一个提示框**。
- **期望**：倒计时结束后脚本被执行一次；`data/events.log` 里有执行记录与退出码；设置页「状态」标签能看到结果。
- **不符合**：执行了两次；或完全没有记录（连失败记录都没有）。

### 3.5 取消

- **操作**：同样 10 秒倒计时，在第 5 秒点「取消关机」。
- **期望**：**一条都不执行**，`events.log` 里没有执行记录。
- **不符合**：取消后脚本仍然执行了。

### 3.6 三端

- **Windows**：已完整验证，是主测试平台。
- **macOS**：**「关机」已经真机跑通，机器实际关机**（Apple Silicon / macOS 27.2 / DSH Desktop，插件 `1.6.1-beta.3`：武装 → 任务结束 → 倒计时 → 命令送出 → 系统接受 → 关机）。**前提是没有应用阻止关机** —— 终端跑着前台命令、编辑器有未保存文档时会被系统拦下，见第 4 节第一条。**重启、注销、睡眠、休眠尚未真机验证**。
- **Linux**：**尚未真机实测**，只有代码与断言覆盖。如果你手上有机器，请反馈装得上、能挂载、动作区给出的可用性判断是否符合预期。

## 4. 已知限制（请先读这段再判断是不是 bug）

- **macOS 上关机可能被系统拦下**：macOS 会先检查是否有应用声明「我正在忙」。终端里跑着前台命令、编辑器有未保存文档时，系统会拦下并等待确认 —— 这与手动点苹果菜单「关机」被拦是同一种情况，不是插件没发出命令；**把前台应用空出来再跑，就能正常关机**。想让它无条件执行需要 root 权限（`shutdown -h now`），插件刻意不碰提权。测的时候先把终端里的长命令停掉。
- **倒计时由插件自己数**。DSH 在倒计时期间被杀掉或崩溃，动作就**不会**执行。旧版用的是系统定时器（`shutdown /t N`），那种情况下仍然会关。这是刻意的取舍：宁可漏关，也不错关。
- 脚本以**你当前用户的权限**运行，插件**不审查**脚本内容，也不对其安全性作担保。
- `restart-dsh` 在列表里但**置灰**：重启 DSH 需要 Electron 主进程的 `app.relaunch()`，插件够不着。
- **macOS 锁屏不可用**：会明确报「不支持」，不会半锁。
- **macOS 上「可用但仍是 unknown」是正常的**：能解析到命令的动作报 `"unknown"` + `needs-elevation`，因为系统可能在真正执行那一刻才决定。`"unknown"` 可以武装，但它不是「一定成功」的承诺。真机上已经成功关机一次；**重启 / 注销 / 睡眠 / 休眠仍未验证**。
- **Linux 注销会连带结束 DSH 自己**（DSH 跑在该用户会话里），用它测注销等于把 DSH 一起关掉。
- 脚本执行输出 stdout / stderr **各截 4096 字节**，超出部分看不到。
- 脚本存在插件的可写数据目录（`data/scripts/`），不在 npm 包目录里；升级插件不会带走它们。
- 从 1.6.0 升上来时 `config.json` 会升到新 schema，旧配置自动迁移；`customArgv` 这类内部试验字段从未随任何版本发布，不参与迁移。
- beta.1 之后各版（beta.2、beta.3）**没有配置格式变化**：schema 在 beta.1 就定稿为 4，后续只改行为，所以不用改文件、不用重装配置，覆盖安装后重启 DSH 就行。

## 5. 怎么反馈

请带上这些，越具体越好：

1. `data/config.json` 里**相关片段**：profile 的 `action` 与 `scriptId`，以及顶层 `scripts[]` 里那一条（`name` / `ext` / `bytes` / `sha256`）；
2. `data/events.log` 的**尾部**（最近 20 行左右）；
3. 系统版本（Windows 版本 / macOS 版本 / 发行版与内核）、DSH 版本、插件版本；
4. 复现步骤：倒计时设了多少秒、第几秒做的操作、点了哪个按钮。

**不要贴脚本内容**，给 `ext`、`bytes`、`sha256` 就够定位了。

## 6. 别做什么

- 别拿它测「真的把生产机按时关掉」，请用一台可以随时重启的机器。
- 别上传来源不明的脚本，尤其是从网上下载、你自己没逐行看过的。
- 别在多人共用的机器上开自定义动作。
- 别把 beta 的行为当承诺：这一版的目的就是找出上面那些限制之外还有什么没考虑到。
