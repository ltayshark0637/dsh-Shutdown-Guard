# v1.6.2 测试与验证指南

> **中文** · [English](BETA.en.md) · [Русский](BETA.ru.md)

## 1. 这是什么版本

`1.6.2` 是**正式版**；本文保留为回归清单，发布后仍可照此复验。

- 想复验某个具体行为，按下面第 3 节逐条走即可；它们描述的期望在 1.6.2 上成立。
- 安装时请显式带上版本号（见第 2 节），这样将来 `latest` 变了也不会装错。
- 1.6.2 之后行为可能继续演进，文档以本文件为准。

## 2. 怎么装

```bash
npm i -g dsh-shutdown-guard@1.6.2
```

装完**完整退出 DSH 再打开**（macOS 上用 ⌘Q 退出，关窗口和刷新页面都不算）。客户端 bundle 只在启动时编进模块图，只关窗口或刷新页面不会加载新代码；改完代码、升级完插件同理。

已经装着 1.6.1 的，直接装 1.6.2 覆盖即可 —— 本文件的测试项与期望行为描述的都是 1.6.2。

**升级前先备份 `data/config.json` 与 `data/scripts/`**：它们就在插件包目录里，`npm i` 覆盖升级会替换整个包目录（原因见第 4 节倒数第三条）。

回滚：

```bash
npm i -g dsh-shutdown-guard@1.6.1
```

（本机 PowerShell 若禁止 `npm.ps1`，请用 `npm.cmd`。）

平台：`package.json` 里的 `os` 限制已经删掉，macOS / Linux 现在可以正常 `npm install`（行为上的成熟度见 3.6）。

从 beta.1 升上来**不需要任何手工迁移**：配置 schema 在 beta.1 已经定稿为 4、脚本库把它推到 5，后续版本只改行为、不改配置格式，装上新版本重启 DSH 即可。

## 3. 这一版要测什么

每条都按「怎么操作 / 期望看到什么 / 不符合时是什么现象」写。测完请按第 5 节反馈。

**开始之前先武装。** 插件不会因为任务结束就自己开始倒计时 —— 顺序是「先把卡片武装起来，再去跑任务」。没武装就等，什么都不会发生。

### 3.1 上传脚本

- **操作**：设置 → 守夜 → 自定义命令 → 选择文件，分别试 `js` / `cmd` / `bat` / `py` / `ps1` 各一个（内容可以只有一行无害语句）。
- **期望**：胶囊出现，显示扩展名标志色 + 文件名；输入框能改成自定义显示名；点「移除」后胶囊消失、动作区回到未选状态。
- **不符合**：胶囊空着、显示名改完又弹回、移除后仍能武装。

### 3.2 免责勾选

- **操作**：上传一个脚本，不勾免责直接点「武装」；再勾上武装；然后换一个脚本内容再武装。
- **期望**：未勾选时武装被拒并给出原因；勾上后能武装；**换脚本后勾选自动失效**，需要重新确认。
- **不符合**：不勾也能武装；换了脚本还能直接武装（说明 sha256 校验没生效）。

### 3.3 解释器缺失

- **操作**：在一台**没有安装 Python** 的机器上传 `.py`；或在没有 node 的环境上传 `.js`。
- **期望**：动作区显示不可用并说明原因（缺少解释器），武装被拒；换回 `.bat` 或 `.ps1` 后恢复正常。
- **不符合**：显示可用、到点却什么都没执行，且日志里没有解释。

### 3.4 到点执行

- **操作**：选「自定义命令」，倒计时设成 10 秒，脚本写成**只写一个文件**或**弹一个提示框**。
- **期望**：倒计时结束后脚本被执行一次；`data/events.log` 里有执行记录与退出码；设置页「状态」标签能看到结果。
- **不符合**：执行了两次；或完全没有记录（连失败记录都没有）。

### 3.5 取消

- **操作**：同样 10 秒倒计时，在第 5 秒点「取消关机」。
- **期望**：**一条都不执行**，`events.log` 里没有执行记录。
- **不符合**：取消后脚本仍然执行了。

### 3.6 三端

- **Windows**：已完整验证，是主测试平台。
- **macOS**：**关机、重启、睡眠、注销四项都已经真机跑通**（Apple Silicon / macOS 27.2 / DSH Desktop：武装 → 任务结束 → 倒计时 → 命令送出 → 系统接受 → 机器实际关机 / 重启 / 睡下 / 结束登录会话）。**前提是没有应用阻止** —— 终端跑着前台命令、编辑器有未保存文档时会被系统拦下，见第 4 节第一条。**休眠在 macOS 上不提供**：系统没有用户级休眠命令，插件也不会把睡眠冒充成休眠，需要省电就用「睡眠」（见架构文档 §7）；**锁屏不支持**，见第 4 节。
- **Linux**：**六个动作已在真机验证执行成功**（Ubuntu 24.04.5 LTS / 桌面会话，插件 `1.6.1-beta.5`）：关机、重启、睡眠、休眠、锁屏、注销都能真正执行。**已知限制**：「注销」结束的是整个登录会话，DSH 会随之退出、此后不再有事件记录（见第 4 节）。**尚未验证**：真实限流 / 超时下的自动重试；插件重载后武装状态是否保留。

## 4. 已知限制（请先读这段再判断是不是 bug）

- **macOS 上关机可能被系统拦下**：macOS 会先检查是否有应用声明「我正在忙」。终端里跑着前台命令、编辑器有未保存文档时，系统会拦下并等待确认 —— 这与手动点苹果菜单「关机」被拦是同一种情况，不是插件没发出命令；**把前台应用空出来再跑，就能正常关机**。想让它无条件执行需要 root 权限（`shutdown -h now`），插件刻意不碰提权。测的时候先把终端里的长命令停掉。
- **倒计时由插件自己数**。DSH 在倒计时期间被杀掉或崩溃，动作就**不会**执行。旧版用的是系统定时器（`shutdown /t N`），那种情况下仍然会关。这是刻意的取舍：宁可漏关，也不错关。
- 脚本以**你当前用户的权限**运行，插件**不审查**脚本内容，也不对其安全性作担保。
- `restart-dsh` 在列表里但**置灰**：重启 DSH 需要 Electron 主进程的 `app.relaunch()`，插件够不着。
- **macOS 上「锁屏」不可用、「休眠」不会出现**：锁屏会明确报「不支持」，不会半锁；休眠因为系统没有用户级休眠命令，插件不把睡眠冒充成休眠 —— 需要省电就用「睡眠」。
- **macOS 上「可用但仍是 unknown」是正常的**：能解析到命令的动作报 `"unknown"` + `needs-elevation`，因为系统可能在真正执行那一刻才决定。`"unknown"` 可以武装，但它不是「一定成功」的承诺。真机上关机、重启、睡眠、注销四个动作都已经成功执行过；**休眠在 macOS 上不提供**（没有用户级休眠命令，也不拿睡眠冒充），**锁屏不支持**（没有可靠 CLI）。
- **Linux 的「注销」会连带结束 DSH 自己**（DSH 跑在该用户会话里，`loginctl terminate-user` 关的是整个会话），所以注销之后不再有事件记录。这不是缺陷，是那条命令的语义。
- **`needs-elevation` 是保守标注，不是检测结果**：非 Windows 上一律标成「可能需授权」，实测 Ubuntu 24.04.5 上六个动作都不需要额外提权；不要读成「必须 sudo」。
- **Linux 上可能弹一次认证框**：某个动作首次以非 0 退出时，宿主会用 `pkexec` 重试一次（最多等 120 秒），polkit 可能要求输入密码。前提是「非 0 ＝ 没执行成功」；若某条命令产生了副作用却仍返回非 0，极端情况下会重复执行一次。
- **没有定时器就不自动重试**：宿主给不出定时能力时 `retryAt` 置 0、事件日志记 `log.retryUnavailable`，界面不会显示「N 秒后重试」。
- 脚本执行输出 stdout / stderr **各截 4096 字节**，超出部分看不到。
- **配置、脚本、事件日志都在插件包目录里的 `data/`**（`data/config.json`、`data/scripts/`、`data/events.log`）：它们没被打进 npm 包，但位置就在包目录内部，而 `npm i` 覆盖升级会替换整个包目录 —— `data/` 可能一起没了。**升级前先备份 `data/config.json` 与 `data/scripts/`。**
- 从 1.6.0 升上来时 `config.json` 会升到新 schema，旧配置自动迁移；`customArgv` 这类内部试验字段从未随任何版本发布，不参与迁移。
- 1.6.2 的 schema 是 5（多出全局脚本库 `scripts[]`）；从 1.6.0 升上来会在启动时自动迁移并立刻写盘，不需要手工改文件，覆盖安装后重启 DSH 即可。从 1.6.1 升到 1.6.2 配置格式没有变化，不需要迁移。

## 5. 怎么反馈

请带上这些，越具体越好：

1. `data/config.json` 里**相关片段**：profile 的 `action` 与 `scriptId`，以及顶层 `scripts[]` 里那一条（`name` / `ext` / `bytes` / `sha256`）；
2. `data/events.log` 的**尾部**（最近 20 行左右）；
3. 系统版本（Windows 版本 / macOS 版本 / 发行版与内核）、DSH 版本、插件版本；
4. 复现步骤：倒计时设了多少秒、第几秒做的操作、点了哪个按钮。

**不要贴脚本内容**，给 `ext`、`bytes`、`sha256` 就够定位了。

## 6. 别做什么

- 别拿它测「真的把生产机按时关掉」，请用一台可以随时重启的机器。
- 别上传来源不明的脚本，尤其是从网上下载、你自己没逐行看过的。
- 别在多人共用的机器上开自定义动作。
- 别把本文当成对所有环境的保证：上面写的是我们实测过的范围，范围之外请按第 5 节反馈实际情况。
