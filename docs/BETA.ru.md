# Руководство по тестированию и проверке v1.6.2

> [中文](BETA.md) · [English](BETA.en.md) · **Русский**

## 1. Что это за версия

`1.6.2` — **стабильная версия**; этот документ сохраняется как чек-лист регрессии, по которому можно пройти и после релиза.

- Чтобы перепроверить конкретное поведение, идите по разделу 3 пункт за пунктом; описанные ожидания верны для 1.6.2.
- При установке указывайте версию явно (см. раздел 2), чтобы изменившийся `latest` не поставил что-то другое.
- После 1.6.2 поведение может продолжать меняться; в части документации главный — этот файл.

## 2. Как установить

```bash
npm i -g dsh-shutdown-guard@1.6.2
```

После установки **полностью закройте DSH и запустите снова** (на macOS — через ⌘Q; закрыть окно или обновить страницу недостаточно). Клиентский bundle компилируется в граф модулей только при запуске, поэтому закрытие окна и обновление страницы новый код не загружают; то же самое после правки кода или обновления плагина.

Если стоит 1.6.1, просто поставьте 1.6.2 поверх — все пункты и описания ожидаемого поведения здесь относятся к 1.6.2.

**Перед обновлением сделайте резервную копию `data/config.json` и `data/scripts/`**: они лежат внутри каталога пакета плагина, а `npm i` заменяет весь этот каталог (причина — третий пункт с конца раздела 4).

Откат:

```bash
npm i -g dsh-shutdown-guard@1.6.1
```

(Если локальный PowerShell запрещает `npm.ps1`, используйте `npm.cmd`.)

Платформа: ограничение `os` в `package.json` удалено, поэтому на macOS / Linux теперь нормально работает `npm install` (о зрелости поведения см. 3.6).

Обновление с beta.1 **не требует ручной миграции**: схема конфигурации была зафиксирована как 4 ещё в beta.1, а библиотека скриптов подняла её до 5; последующие версии меняют только поведение, но не формат — достаточно установить и перезапустить DSH.

## 3. Что проверять в этой версии

Каждый пункт описан по схеме «что делать / что должно быть видно / как выглядит несоответствие». О результате сообщите по разделу 5.

**Сначала взведите карточку.** Плагин не начинает отсчёт просто потому, что задачи закончились — порядок такой: «сначала взводим карточку, потом запускаем работу». Если не взвести, ничего не произойдёт, сколько ни ждать.

### 3.1 Загрузка скрипта

- **Действие**: Настройки → Ночной дозор → Пользовательская команда → Выбрать файл; попробуйте по одному файлу `js` / `cmd` / `bat` / `py` / `ps1` (содержимое может быть одной безвредной строкой).
- **Ожидается**: появляется плашка с цветом-флагом расширения и именем файла; в поле ввода можно задать своё отображаемое имя; после нажатия «Удалить» плашка исчезает, а область действия возвращается в невыбранное состояние.
- **Несоответствие**: плашка пустая, отображаемое имя после правки откатывается, или после удаления всё ещё можно включить режим.

### 3.2 Отметка о предупреждении

- **Действие**: загрузите скрипт и нажмите «Включить» без отметки о предупреждении; затем поставьте отметку и включите; затем измените содержимое скрипта и включите снова.
- **Ожидается**: без отметки включение отклоняется с указанием причины; с отметкой включение проходит; **после смены скрипта отметка автоматически аннулируется**, и подтверждение нужно повторить.
- **Несоответствие**: включение проходит без отметки; или сразу после смены скрипта включение всё ещё проходит (значит, проверка sha256 не действует).

### 3.3 Отсутствующий интерпретатор

- **Действие**: на машине **без установленного Python** загрузите `.py`; или в окружении без node загрузите `.js`.
- **Ожидается**: область действия показывает недоступность с причиной (нет интерпретатора), включение отклоняется; после возврата к `.bat` или `.ps1` всё снова работает.
- **Несоответствие**: показано, что доступно, но в момент срабатывания ничего не выполняется, и в журнале нет объяснения.

### 3.4 Выполнение в момент срабатывания

- **Действие**: выберите «Пользовательская команда», задайте отсчёт 10 секунд, а скрипт напишите так, чтобы он **только записывал один файл** или **показывал окно с сообщением**.
- **Ожидается**: после окончания отсчёта скрипт выполняется один раз; в `data/events.log` есть запись о выполнении и код выхода; на вкладке «Состояние» страницы настроек виден результат.
- **Несоответствие**: выполнено дважды; или записей нет вообще (даже записи о неудаче).

### 3.5 Отмена

- **Действие**: тот же отсчёт 10 секунд, на 5-й секунде нажмите «Отменить выключение».
- **Ожидается**: **ни один скрипт не выполняется**, в `events.log` нет записи о выполнении.
- **Несоответствие**: после отмены скрипт всё равно выполнился.

### 3.6 Три платформы

- **Windows**: полностью проверено, это основная тестовая платформа.
- **macOS**: **выключение, перезагрузка, сон и выход из сеанса успешно выполнены на реальной машине** (Apple Silicon / macOS 27.2 / DSH Desktop: взвод → задачи закончились → отсчёт → команда отправлена → система приняла → машина действительно выключилась, перезагрузилась, ушла в сон или завершила сеанс). **При условии, что ни одно приложение не блокирует действие** — терминал с командой на переднем плане или редактор с несохранёнными документами заставляют систему придержать его, см. первый пункт раздела 4. **У гибернации в macOS нет пользовательской команды**, поэтому плагин не выполняет настоящую гибернацию (действие сводится ко сну, см. раздел 7 архитектурного документа); **блокировка экрана не поддерживается**, см. раздел 4.
- **Linux**: **все шесть действий проверены на реальной машине** (Ubuntu 24.04.5 LTS / сеанс рабочего стола, плагин `1.6.1-beta.5`): выключение, перезагрузка, сон, гибернация, блокировка экрана и выход из сеанса действительно выполняются. **Известное ограничение**: «выход из сеанса» завершает весь сеанс входа, поэтому DSH завершается вместе с ним и события больше не записываются (см. раздел 4). **Пока не проверено**: автоматические повторы при реальном ограничении частоты / тайм-аутах и сохраняется ли взведённое состояние после перезагрузки плагина.

## 4. Известные ограничения (прочитайте до того, как решите, что это баг)

- **В macOS выключение может быть остановлено системой**: сначала она проверяет, не заявило ли какое-то приложение «я занято». Терминал с командой на переднем плане или редактор с несохранёнными документами заставляют её ждать подтверждения — это ровно то же, что происходит при ручном «Выключить» из меню Apple, и это не значит, что плагин не отправил команду; **освободите передний план — и выключение пройдёт нормально**. Безусловное выполнение требует root (`shutdown -h now`), а плагин намеренно не трогает повышение прав. Перед тестом остановите долгие команды в терминале.
- **Отсчёт ведёт сам плагин.** Если во время отсчёта DSH будет убит или упадёт, действие **не** выполнится. В старой версии использовался системный таймер (`shutdown /t N`), и в таком случае выключение всё равно произошло бы. Это осознанный компромисс: лучше пропустить выключение, чем выключить не вовремя.
- Скрипты выполняются с **правами вашего текущего пользователя**; плагин **не проверяет** содержимое скриптов и не гарантирует их безопасность.
- `restart-dsh` есть в списке, но **неактивен**: перезапуск DSH требует `app.relaunch()` из главного процесса Electron, до которого плагин не может добраться.
- **Блокировка экрана в macOS недоступна**: явно сообщается «не поддерживается», частичной блокировки не бывает.
- **В macOS «доступно, но всё равно unknown» — это нормально**: действие, для которого команда нашлась, сообщает `"unknown"` + `needs-elevation`, потому что система может решить только в момент выполнения. `"unknown"` можно взвести, но это не обещание, что всё сработает. На реальной машине выключение, перезагрузка, сон и выход из сеанса уже проходили успешно; **гибернация в macOS не предлагается** (пользовательской команды нет), **блокировка экрана не поддерживается** (надёжного CLI нет).
- **В Linux выход из сеанса завершает и сам DSH** (DSH работает внутри сеанса этого пользователя, а `loginctl terminate-user` завершает весь сеанс), поэтому после этого событий больше не записывается. Это не дефект, а смысл самой команды.
- **`needs-elevation` — консервативная пометка, а не результат проверки**: на не-Windows всё помечается как «может потребоваться авторизация»; на реальном Ubuntu 24.04.5 все шесть действий выполнились без дополнительных прав. Не читайте это как «нужен sudo».
- **В Linux может появиться одно окно аутентификации**: если действие впервые завершилось с ненулевым кодом, хост повторяет его один раз через `pkexec` (ожидание до 120 секунд), и polkit может запросить пароль. Предпосылка — «ненулевой код означает, что не выполнилось»; если команда дала эффект, но всё равно вернула ненулевой код, в крайнем случае она выполнится дважды.
- **Нет таймера — нет автоматического повтора**: если хост не может дать таймер, `retryAt` выставляется в 0, в журнал пишется `log.retryUnavailable`, а интерфейс перестаёт показывать «повтор через N секунд».
- Вывод скрипта stdout / stderr **обрезается по 4096 байт каждый**, всё сверх этого не видно.
- **Конфиг, скрипты и журнал событий лежат в `data/` внутри каталога пакета плагина** (`data/config.json`, `data/scripts/`, `data/events.log`): в npm-архив они не попадают, но место у них — внутри каталога пакета, а обновление через `npm i` заменяет весь этот каталог, поэтому `data/` может исчезнуть вместе с ним. **Перед обновлением сделайте резервную копию `data/config.json` и `data/scripts/`.**
- При обновлении с 1.6.0 `config.json` поднимается до новой схемы, старый конфиг мигрируется автоматически; такие внутренние экспериментальные поля, как `customArgv`, никогда не выходили ни в одной версии и в миграции не участвуют.
- В 1.6.2 схема — 5 (появилась глобальная библиотека скриптов `scripts[]`); при обновлении с 1.6.0 миграция выполняется при запуске и сразу записывается на диск — править файлы вручную не нужно, достаточно установить поверх и перезапустить DSH. При обновлении с 1.6.1 формат конфигурации не меняется, миграция не нужна.

## 5. Как сообщать о проблемах

Приложите следующее, чем конкретнее, тем лучше:

1. **относящийся к делу фрагмент** `data/config.json`: `action` и `scriptId` профиля, а также та самая запись в верхнеуровневом `scripts[]` (`name` / `ext` / `bytes` / `sha256`);
2. **хвост** `data/events.log` (примерно последние 20 строк);
3. версию системы (версия Windows / версия macOS / дистрибутив и ядро), версию DSH, версию плагина;
4. шаги воспроизведения: на сколько секунд был выставлен отсчёт, на какой секунде вы действовали, на какую кнопку нажали.

**Не вставляйте содержимое скрипта**, `ext`, `bytes` и `sha256` достаточно для его идентификации.

## 6. Чего не делать

- Не проверяйте на нём «действительно вовремя выключить рабочую машину» — используйте машину, которую можно перезагрузить в любой момент.
- Не загружайте скрипты неизвестного происхождения, особенно скачанные из интернета и не прочитанные вами построчно.
- Не включайте пользовательские действия на машине, которой пользуются несколько человек.
- Не считайте этот документ гарантией для любых окружений: выше описан диапазон, который мы реально проверили; за его пределами сообщите фактическую ситуацию по разделу 5.
