# Руководство по тестированию v1.6.1-beta.2

> Оригинал на китайском: [BETA.md](BETA.md)
> English version: [BETA.en.md](BETA.en.md)

## 1. Что это за версия

`1.6.1-beta.2` — это **бета-версия**, которая продолжает beta.1 и доводит до рабочего состояния возможность «загрузить скрипт и выполнить его в момент срабатывания». Этот документ описывает текущую бету, а не исторический снимок.

- **Не устанавливайте её на рабочих машинах** и не используйте для проверки «действительно вовремя выключить рабочую машину».
- `latest` в npm по-прежнему `1.6.0`; для установки беты нужно явно указать номер версии.
- Во время беты поведение может меняться в любой момент; в части документации главный — этот файл.

## 2. Как установить

```bash
npm i -g dsh-shutdown-guard@1.6.1-beta.2
```

После установки **полностью закройте DSH и запустите снова**. Клиентский bundle компилируется в граф модулей только при запуске; обновление страницы не загружает новый код.

Если уже стоит beta.1, сначала обновитесь до beta.2 и тестируйте по этому руководству — все пункты и описания ожидаемого поведения здесь относятся к beta.2.

Откат:

```bash
npm i -g dsh-shutdown-guard@1.6.0
```

(Если локальный PowerShell запрещает `npm.ps1`, используйте `npm.cmd`.)

Платформа: ограничение `os` в `package.json` удалено, поэтому на macOS / Linux теперь нормально работает `npm install` (о зрелости поведения см. 3.6).

Обновление с beta.1 до beta.2 **не требует никакой ручной миграции**: схема конфигурации была зафиксирована как 4 ещё в beta.1, beta.2 меняет только поведение, но не формат конфигурации — достаточно поставить новую версию и перезапустить DSH.

## 3. Что проверять в этой версии

Каждый пункт описан по схеме «что делать / что должно быть видно / как выглядит несоответствие». О результате сообщите по разделу 5.

### 3.1 Загрузка скрипта

- **Действие**: Настройки → Ночной дозор → Пользовательская команда → Выбрать файл; попробуйте по одному файлу `js` / `cmd` / `bat` / `py` / `ps1` (содержимое может быть одной безвредной строкой).
- **Ожидается**: появляется плашка с цветом-флагом расширения и именем файла; в поле ввода можно задать своё отображаемое имя; после нажатия «Удалить» плашка исчезает, а область действия возвращается в невыбранное состояние.
- **Несоответствие**: плашка пустая, отображаемое имя после правки откатывается, или после удаления всё ещё можно включить режим.

### 3.2 Отметка о предупреждении

- **Действие**: загрузите скрипт и нажмите «Включить» без отметки о предупреждении; затем поставьте отметку и включите; затем измените содержимое скрипта и включите снова.
- **Ожидается**: без отметки включение отклоняется с указанием причины; с отметкой включение проходит; **после смены скрипта отметка автоматически аннулируется**, и подтверждение нужно повторить.
- **Несоответствие**: включение проходит без отметки; или сразу после смены скрипта включение всё ещё проходит (значит, проверка sha256 не действует).

### 3.3 Отсутствующий интерпретатор

- **Действие**: на машине **без установленного Python** загрузите `.py`; или в окружении без node загрузите `.js`.
- **Ожидается**: область действия показывает недоступность с причиной (нет интерпретатора), включение отклоняется; после возврата к `.bat` или `.ps1` всё снова работает.
- **Несоответствие**: показано, что доступно, но в момент срабатывания ничего не выполняется, и в журнале нет объяснения.

### 3.4 Выполнение в момент срабатывания

- **Действие**: выберите «Пользовательская команда», задайте отсчёт 10 секунд, а скрипт напишите так, чтобы он **только записывал один файл** или **показывал окно с сообщением**.
- **Ожидается**: после окончания отсчёта скрипт выполняется один раз; в `data/events.log` есть запись о выполнении и код выхода; на вкладке «Состояние» страницы настроек виден результат.
- **Несоответствие**: выполнено дважды; или записей нет вообще (даже записи о неудаче).

### 3.5 Отмена

- **Действие**: тот же отсчёт 10 секунд, на 5-й секунде нажмите «Отменить выключение».
- **Ожидается**: **ни один скрипт не выполняется**, в `events.log` нет записи о выполнении.
- **Несоответствие**: после отмены скрипт всё равно выполнился.

### 3.6 Три платформы

- **Windows**: полностью проверено, это основная тестовая платформа.
- **macOS / Linux**: **реализовано, но на реальном железе не проверялось**. Если у вас есть машина, сообщите заодно, ставится ли плагин, монтируется ли он и совпадает ли оценка доступности в области действия с ожиданиями.

## 4. Известные ограничения (прочитайте до того, как решите, что это баг)

- **Отсчёт ведёт сам плагин.** Если во время отсчёта DSH будет убит или упадёт, действие **не** выполнится. В старой версии использовался системный таймер (`shutdown /t N`), и в таком случае выключение всё равно произошло бы. Это осознанный компромисс: лучше пропустить выключение, чем выключить не вовремя.
- Скрипты выполняются с **правами вашего текущего пользователя**; плагин **не проверяет** содержимое скриптов и не гарантирует их безопасность.
- `restart-dsh` есть в списке, но **неактивен**: перезапуск DSH требует `app.relaunch()` из главного процесса Electron, до которого плагин не может добраться.
- **Блокировка экрана в macOS недоступна**: явно сообщается «не поддерживается», частичной блокировки не бывает.
- **В Linux выход из сеанса завершает и сам DSH** (DSH работает внутри сеанса этого пользователя), поэтому проверять на нём выход из сеанса — значит закрыть DSH вместе с ним.
- Вывод скрипта stdout / stderr **обрезается по 4096 байт каждый**, всё сверх этого не видно.
- Скрипты лежат в записываемом каталоге данных плагина (`data/scripts/`), а не в каталоге пакета npm; обновление плагина их не удаляет.
- При обновлении с 1.6.0 `config.json` поднимается до новой схемы, старый конфиг мигрируется автоматически; такие внутренние экспериментальные поля, как `customArgv`, никогда не выходили ни в одной версии и в миграции не участвуют.
- beta.1 → beta.2 — **изменений формата конфигурации нет**: схема была зафиксирована как 4 ещё в beta.1, beta.2 меняет только поведение, поэтому не нужно править файлы и заново настраивать конфиг — достаточно установить поверх и перезапустить DSH.

## 5. Как сообщать о проблемах

Приложите следующее, чем конкретнее, тем лучше:

1. **относящийся к делу фрагмент** `data/config.json`: `action` профиля, `script` (`name` / `ext` / `bytes` / `sha256`) и `scriptAck`;
2. **хвост** `data/events.log` (примерно последние 20 строк);
3. версию системы (версия Windows / версия macOS / дистрибутив и ядро), версию DSH, версию плагина;
4. шаги воспроизведения: на сколько секунд был выставлен отсчёт, на какой секунде вы действовали, на какую кнопку нажали.

**Не вставляйте содержимое скрипта**, `ext`, `bytes` и `sha256` достаточно для его идентификации.

## 6. Чего не делать

- Не проверяйте на нём «действительно вовремя выключить рабочую машину» — используйте машину, которую можно перезагрузить в любой момент.
- Не загружайте скрипты неизвестного происхождения, особенно скачанные из интернета и не прочитанные вами построчно.
- Не включайте пользовательские действия на машине, которой пользуются несколько человек.
- Не считайте поведение беты обещанием: цель этой версии — найти то, что не учтено помимо перечисленных ограничений.
