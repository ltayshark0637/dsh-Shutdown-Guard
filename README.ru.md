Добавляет в боковую панель DeepSeek Harness карточку «выключить, когда все задачи готовы» — сразу под «Центром навыков» и над списком сессий, в реальном времени следуя за состоянием задач.

Она не выключает компьютер в момент, когда задача закончилась. Фоновые задачи ещё идут, сессия завершилась ошибкой, агент ждёт вашего ответа — всё это её останавливает. Она действует только когда выключать действительно безопасно, и пишет причину прямо на карточке.

**▶ [Интерактивное демо](https://ltayshark0637.github.io/dsh-Shutdown-Guard/demo.html)** — посмотреть, как это выглядит и как принимается решение, ничего не устанавливая. Все данные генерируются локально, в сеть ничего не уходит.

## Установка

**Рекомендуется: установка из локального каталога.** Плагин хранит конфигурацию, загруженные скрипты и журнал событий в папке `data/` внутри каталога плагина; только каталог, на который DSH указывает напрямую, сохраняет её при обновлении.

```bash
git clone https://github.com/ltayshark0637/dsh-Shutdown-Guard
```

Дальше: настройки DSH → Плагины → Добавить, укажите **абсолютный путь к этому каталогу** → установить → полностью выйти из DSH и открыть его заново (перезагрузка страницы не помогает).

Для обновления выполните `git pull` в этом каталоге и полностью перезапустите DSH. **`data/` не затрагивается** — конфигурация, загруженные скрипты и журнал событий остаются на месте.

> **Ставить через npm или GitHub тоже можно, но перед обновлением сделайте резервную копию `data/`**: эти два способа ставят копию, которой управляет менеджер пакетов, обновление заменяет каталог плагина целиком, и конфигурация, загруженные скрипты и журнал событий внутри могут пропасть вместе с ним. Если не хочется об этом думать, используйте установку из локального каталога выше.

Когда нужен путь через registry (при ограниченной сети удобнее npm — он идёт через registry; вариант с GitHub под капотом это `pnpm add github:...` и требует клонирования):

```bash
dsh plugin --profile web add dsh-shutdown-guard
```

Без версии ставится последняя стабильная; чтобы закрепить версию, укажите её явно:

```bash
dsh plugin --profile web add dsh-shutdown-guard@1.6.2
```

Или напрямую с GitHub:

```bash
dsh plugin --profile web add github:ltayshark0637/dsh-Shutdown-Guard
```

Все три ставят копию, которой управляет менеджер пакетов: обновление заменяет каталог плагина целиком, поэтому **сначала сделайте резервную копию `data/`**.

## Настройки

<p align="center"><img src="https://ltayshark0637.github.io/dsh-Shutdown-Guard/screenshots/12-settings-dark.png" width="380" alt="Страница настроек (тёмная)"></p>

Четыре вкладки; открывается на «Внешнем виде», все переключатели применяются сразу.

- **Внешний вид**: стиль карточки (три карточки с миниатюрами, миниатюры следуют за языком и фоном), тема, складывать по умолчанию, компактное плавающее окно, язык интерфейса.
- **Ночная вахта**: сначала переключатель «своя конфигурация» отдельной строкой, при включении появляется список конфигураций (переключить, сделать по умолчанию, переименовать, удалить, создать); ниже — четыре строки условий, «автоответ AFK» и список **что сделать по истечении отсчёта** (выключение / перезагрузка / сон / гибернация / блокировка экрана / выход из системы / перезапуск DSH / свой скрипт).
- **Уведомления**: общий переключатель и четыре отдельных (начался отсчёт, скоро выключение, первая блокировка, блокировка снята).
- **Состояние**: текущая блокировка, почему не выключилось в прошлый раз, последние события.

## Частые вопросы

**В: А оно не выключит компьютер по ошибке?**
О: Конфигурация по умолчанию требует одновременного выполнения четырёх условий — «все сессии свободны», «нет фоновых задач», «в этой партии не было ошибок» и «вы сами взвели карточку»; нарушение любого из них отменяет или пропускает запуск, а вручную остановленная вами задача уже исключена.

**В: Я взвёл, но выключения не было.**
О: Откройте «Состояние» → «почему не выключилось в прошлый раз» — там названа причина (фоновые задачи, ошибки, не взведено и т. п.).

**В: Можно передумать во время отсчёта?**
О: Да — нажмите «отменить выключение» на карточке. После отмены в этом раунде **не будет отправлено ни одной команды**, а карточка остаётся взведённой для следующей партии; отправленную команду отозвать уже нельзя.

**В: Поменял настройку, ничего не произошло.**
О: И хост, и клиентский бандл загружаются только при старте DSH; HMR для локально подключённых плагинов не работает.

**В: Поддерживаются ли macOS и Linux?**
О: По платформам, и разница здесь важна:

- **Windows**: проверен полностью, включая реальное выполнение выключения / перезагрузки / сна; **«перезапуск DSH» проверен на реальной машине в настольной сборке** — всё приложение завершается и возвращается само, а при следующем запуске в журнале событий появляется запись «перезапуск выполнен».
- **macOS**: **выключение, перезагрузка, сон и выход из сеанса проверены на реальной машине** (Apple Silicon / macOS 27.2 / DSH Desktop): плагин отправил команду, система её приняла, и машина действительно выключилась, перезагрузилась, ушла в сон или завершила сеанс. **При условии, что ни одно приложение не блокирует действие** — терминал с командой на переднем плане или редактор с несохранёнными документами заставляют macOS придержать его и ждать подтверждения, как при ручном «Выключить» из меню Apple. **Гибернация в macOS не предлагается**: пользовательской команды гибернации нет, и плагин не выдаёт сон за гибернацию — для экономии энергии используйте «Сон». **Блокировка экрана не поддерживается** — надёжного CLI нет, поэтому лучше отказаться, чем блокировать наполовину.
- **Linux**: **все шесть действий проверены на реальной машине** (Ubuntu 24.04.5 LTS / сеанс рабочего стола, плагин `1.6.1-beta.5`): выключение, перезагрузка, сон, гибернация, блокировка экрана и выход из сеанса действительно выполняются. **Известное ограничение**: «выход из сеанса» завершает весь сеанс входа, поэтому DSH завершается вместе с ним и события больше не записываются — таков смысл `loginctl terminate-user`, а не дефект. **Пока не проверено**: автоматические повторы при реальном ограничении частоты / тайм-аутах и сохраняется ли взведённое состояние после перезагрузки плагина.

На macOS проверка сообщает `"unknown"`, а не `true`: система может решить только в момент выполнения. `"unknown"` означает «взвести можно, но решает система в этот момент» — это не поломка.
